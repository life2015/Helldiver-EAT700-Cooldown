# 0.2.1 近炸触发修正

适配 Steam build 25327279。0.2.0 已在用户游戏中加载成功，但实测只在碰撞时起爆。以下是当前 game.dll 的静态分析结果，不能替代实机验证。

## 明确的角度阻断

1. `0x13ac448` 读取近炸体积查询结果，接在普通射线命中结果之后。
2. `0x13acd9e` 比较结果序号与普通射线命中数；`0x13acdaa` 的 `setae` 标记体积查询结果，保存到候选记录 `+0x35`（该处寻址为 `[rbp+rbx+0x11f5]`）。
3. `0x13ad4e1` 检查这个标记；非零分支在 `0x13ad4fc` 将起爆判定角度设为 `0x42b40000`，即 90.0°。
4. `0x13add80` 读取运行时的起爆角度上限；`0x13add89` 比较该上限与上述角度，`jb` 跳过起爆分支。
5. 上限来自 ProjectileInfo `+136`，在 `0x13aa660` 复制到运行时记录 `+0x88`。原版火次抛上限为 60°，因此拒绝 90° 的体积检测命中。

0.2.1 将该字段设为原生 Flak 的 360°。这也会放宽普通碰撞的起爆角度限制；不声称完全保留原版撞击引信行为。

## 补齐体积查询筛选

`0x13abf08` 分支仅在近炸半径非零时进入，并检查飞行距离是否满足引信启动距离。
它构建沿当前飞行路径的检测体积；`0x13ac048` 读取 ProjectileInfo `+248`，将值作为筛选参数传入 `0x175ba70`。
此字段在旧 Filediver 中被暂名为 `UnkAudioEvent2`，但本调用路径将其用于体积查询，不能按名称当作声音参数。

火次抛值为 `0x393d9518`，Flak 值为 `0xab96e9d8`。0.2.1 采用 Flak 值以匹配其检测筛选规则。未解析出筛选模板的完整成员清单，不声称某一类物体一定触发或一定被排除。

## 修改范围与验证边界

六个四字节字段：136 起爆角度、148 近炸半径、152 延迟、156 到期爆炸载荷、160 启动距离、248 体积查询筛选。
原版火次抛编号 259、碰撞爆炸载荷 316、伤害参数、弹速、火焰资源、外观与其余字节保持一致。
不引入 Flak 的定时寿命，也不复制其子弹头载荷。冷却仍为基础 70 秒。

配置增加上述角度判定和查询路径的原生字节签名；加载时随完整游戏文件哈希一起校验。
离线检查覆盖原始完整弹丸哈希、字段范围、90° 判定回归、六处任意一步写入失败后的还原，以及 v14/v15 实际加载器启动。
